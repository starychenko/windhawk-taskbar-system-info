# Taskbar System Info 1.8.1

This patch fixes the border and dock placement problems reported with the full
TaskbarTweaks theme in [Windhawk issue #6174](https://github.com/ramensoftware/windhawk-mods/issues/6174#issuecomment-6188785874).
No new settings or migration are required. The optional network column and
secondary taskbar copies from 1.8.0 are preserved.

## Changes

- Keep a theme's `Grid.Column`, column span, alignment, `Auto` dimensions,
  margin and padding in control of the outer `Grid#WindhawkTaskbarSystemInfo`.
  Size the inner Viewbox to the actual available slot; avoid competing space
  reservation and move-editor placement while the theme owns that placement.
- Account for arranged siblings when Styler replaces column definitions and
  their reported widths are zero. Allow a dynamic dock in an ancestor's Auto
  column to grow without shrinking the widget on successive layout passes.
- Respect equal/weighted Star allocations and column minima/maxima, including
  capped Pixel columns. Restore automatic placement when the theme is removed,
  and release restored numeric geometry when the theme is applied again.
- Render square WindhawkBlur borders through a small expanded native Border
  clipped back to the Grid's square bounds. The public brush, thickness and
  `CornerRadius=0` stay unchanged; rounded and solid borders use native drawing.
- Refresh the border when only the brush or radius changes, without requiring
  a layout event. Manage subscriptions on each widget's owning UI thread and
  retain secondary cleanup state after a failed callback revocation.

## Verification

On Windows build 26300.9711 with Windhawk 1.7.3:

- `python -B tests/validate-source.py`: 1.8.1 metadata, 32 settings and
  source/documentation checks passed.
- `tests/run-regression.ps1`: 173,515 behavioral checks passed.
- `tests/run-ui-smoke.ps1`: complete isolated XAML suite passed, including
  105 size/font cases, five preview DPI scales, 200,000 generated geometries,
  primary/secondary theme reapplication, render-only border transitions,
  constrained columns and callback cleanup/recovery.
- `tests/run-metrics-smoke.ps1`: live Windows metrics and expected injected
  failure handling passed.
- x64 build, ARM64 cross-build and `git diff --check` passed.

The new regression cases failed on the preceding implementation. Three
independent code reviews and follow-up checks found no confirmed remaining
high- or medium-priority issue in the reviewed changes. There are no GitHub
Actions workflows in this companion repository.

An earlier candidate was also checked in Explorer with the reporter's full
theme and Taskbar Styler 1.10: columns 0/1/3, a 750-DIP dock and recovery,
the original dynamic mode, square/solid border controls and theme removal.
The subsequent review corrections and the final 1.8.1 source were qualified in
isolated XAML; the final source has not been loaded into Explorer. Physical
ARM64, mixed-DPI monitor transfers and other Windows/Styler combinations remain
unverified. The targeted border workaround does not claim to resolve separate
graphics interruptions or the observed Styler/XAML diagnostics crash.

See the [investigation and verification record](../issue-6174-verification.md)
for the causal analysis, live evidence and exact boundaries.

## Install or update

Download **taskbar-system-info.wh.cpp** from this release, replace the source
in Windhawk's mod editor, compile and enable it. This repository release does
not automatically update the official Windhawk catalog or an installed mod.
